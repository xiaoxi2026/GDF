# gdf-need - 需求录入指令

## 触发条件
用户输入 `gdf-need`

## 执行时机
每个新功能/模块开始前

## 前置条件
项目已完成初始化（`gdf-init` 已执行）

## 执行流程

### 第1步：引导用户输入

输出：

```
请描述你的需求。不需要按特定格式，我会主动提问帮你完善。

例如：

"我要开发一个用户管理功能"
"开发产品管理模块，包含增删改查"
"给订单列表增加导出Excel"
"优化一下现有的查询性能"

请直接描述你的需求：
```

---

### 第2步：QA环节（分轮次提问）

收到需求后，**逐轮提问**，每轮 2-3 个问题，避免一次问太多。

#### 第一轮：基础信息

1. **这个需求属于什么类型？**
   - [ ] 新模块 - 从零开始开发
   - [ ] 增加功能 - 为现有模块添加功能
   - [ ] 修改功能 - 调整已有功能
   - [ ] 优化性能 - 改进现有功能

2. **核心目标是什么？**（一句话描述）

3. **预期的使用者是谁？**
   - [ ] 管理员
   - [ ] 普通用户
   - [ ] 所有登录用户
   - [ ] 特定角色：_____

等待用户回答后，继续：

---

#### 第二轮：数据相关

4. **需要管理哪些数据？**（列出主要字段即可）

   例如：名称、编码、价格、库存、状态...

5. **数据从哪里来？**
   - [ ] 新建数据表
   - [ ] 使用现有表（表名：_____)
   - [ ] 外部系统对接

6. **数据量级大概多少？**
   - [ ] 小 (< 1,000 条)
   - [ ] 中 (1,000 - 10万 条)
   - [ ] 大 (> 10万 条)
   - [ ] 不确定

---

#### 第三轮：操作功能

7. **需要支持哪些操作？**

| 操作 | 是否需要 | 备注 |
|------|----------|------|
| 列表查看 | □ | |
| 新增 | □ | |
| 编辑 | □ | |
| 删除 | □ | 软删除/硬删除？ |
| 导出 | □ | 格式：____ |
| 导入 | □ | |
| 批量操作 | □ | |
| 其他 | □ | ____ |

8. **需要搜索/筛选吗？按哪些字段？**

9. **需要分页吗？**
   - [ ] 是，每页 ____ 条
   - [ ] 否，一次性加载

---

#### 第四轮：界面与规则

10. **列表需要显示哪些字段？**

11. **有哪些验证规则？**
    - 必填字段：____
    - 唯一性要求：____
    - 格式要求：____
    - 数值范围：____

12. **是否有特殊业务逻辑？**

    例如：
    - 状态变更规则
    - 权限控制
    - 关联操作
    - 其他：____

---

#### 第五轮：确认性检查（可选）

13. **预期的完成时间？**

14. **有参考的现有功能吗？**（可以减少沟通成本）

15. **有什么需要特别注意的？**

---

### 第3步：生成需求文档

QA 完成后，参考模板 `../templates/requirement.md` 生成需求文档，**保存到 `.gdf/requirements/{模块名}.md`**：

```
请参考文档模板 ../templates/requirement.md 生成需求文档
```

---

### 第4步：等待确认

```
请确认需求文档，输入对应命令：
- 确认 - 锁定需求
- 修改 [内容] - 修改部分内容
- 补充 [内容] - 补充信息
- 取消 - 取消本次需求录入
```

---

### 第5步：确认后锁定

用户确认后：

```
✅ 需求已确认并锁定！

需求文档版本：v1.0
模块名称：[名称]
功能数量：[N]个

下一步：
- 输入 `gdf-split` 进行任务拆解
- 输入 `gdf-status` 查看项目状态
```

用户输入 `取消` 时：

```
已取消需求录入。

输入 `gdf-need` 重新开始，或 `gdf-status` 查看项目状态。
```

---

## 快速模式（适用于简单需求）

对于简单需求，可以跳过详细QA，直接生成简化文档：

```
用户：gdf-need
用户：给用户管理加一个导出Excel功能
AI：（识别为简单需求，跳过详细QA）

生成简化需求文档：
- 目标模块：用户管理
- 新增功能：导出Excel
- 导出格式：xlsx
- 导出范围：全部/当前筛选结果

请确认
```

---

## 常见问题处理

### 需求不明确
- 用户说"做一个功能"
- → 引导："请问是管理什么数据？"

### 需求范围过大
- 用户描述了一个系统
- → 引导："这个系统包含多个模块，建议先从最重要的一个开始"

### 需求频繁变更
- 用户在QA过程中反复修改
- → 提醒："需求确认后可以修改，但会导致任务重新拆解，确认前请仔细检查"

---

## 注意事项

1. **不遗漏问题**：主动提问澄清不确定的地方
2. **逐轮提问**：每轮 2-3 个问题，避免信息过载
3. **记录所有回答**：QA记录要完整保留
4. **等待确认**：生成文档后必须等待用户确认才能锁定
5. **尊重用户节奏**：用户不想回答时可以跳过非关键问题
