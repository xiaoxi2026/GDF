# gdf-refactor - 代码优化指令
version: 1.0.0

## 触发条件
用户输入 `gdf-refactor`

## 执行时机
建议每开发 5-10 个模块后执行一次

## 执行流程

### 第1步：收集代码

输出：

```
请提供需要优化的代码模块。

可以选择：
1. 粘贴所有已开发模块的代码
2. 输入模块名称，只优化指定模块
3. 跳过，查看规范文档建议
```

等待用户提供代码，或指定模块名称。

### 第2步：代码分析

对收集到的代码进行以下分析，参考模板 `../templates/code-analysis.md` 生成报告，**保存到 `.gdf/analysis/{模块名}-analysis.md`**。

### 第3步：生成优化建议

根据分析结果，生成具体优化方案（参考模板中的优化建议部分）。

### 第4步：生成优化代码

对于可优化的代码，生成具体的优化代码（使用代码块格式展示优化前后对比）。

### 第5步：输出总结

```
---

📊 代码优化分析完成！

发现的问题：
- 一致性问题：N 项
- 重复代码：N 处
- 可提炼逻辑：N 项

需要生成优化代码吗？
- 输入 `优化 [问题编号]` - 生成指定问题的优化代码
- 输入 `优化 all` - 生成所有问题的优化代码
- 输入 `跳过` - 稍后处理
```

### 第6步：执行优化

用户确认后，生成并应用优化代码，更新至规范文档。

### 第7步：确认完成

```
✅ 代码优化完成！

已更新：
- [优化项1]
- [优化项2]

规范文档已同步更新。

下一步：
- 输入 `gdf-status` 查看项目状态
- 输入 `gdf-new` 继续开发
```

## 检查项清单

### 一致性检查
- [ ] 变量命名风格统一
- [ ] 函数命名风格统一
- [ ] 缩进和格式一致
- [ ] 注释风格统一
- [ ] 错误处理方式一致
- [ ] 日志记录方式一致

### 代码质量检查
- [ ] 函数长度适中（< 100行）
- [ ] 参数数量合理（< 5个）
- [ ] 无魔法数字
- [ ] 无硬编码字符串
- [ ] 单一职责原则

### 重复代码检查
- [ ] 相似的条件判断
- [ ] 相似的循环逻辑
- [ ] 相似的字符串处理
- [ ] 相似的数据库操作
- [ ] 相似的API调用

## 注意事项

1. **不破坏功能**：优化前先确认现有功能正常
2. **小步迭代**：每次优化聚焦一个问题
3. **保留备份**：重大改动前记录原代码
4. **同步文档**：优化结果要同步到规范文档
