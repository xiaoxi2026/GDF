# gdf-analyze - 项目分析指令
version: 1.0.0

## 触发条件
用户输入 `gdf-analyze`

## 执行时机
- 半路接手某个项目时
- 需要了解模块功能完成情况时
- 项目启动前的调研阶段
- 需要评估代码质量和工作量时

## 执行流程

### 第1步：指定分析范围

输出：

```
📊 项目分析

请指定分析范围：
1. 输入模块名称（如 `user` / `order`）- 只分析指定模块
2. 输入 `全部` - 分析整个项目
3. 输入 `核心` - 分析核心业务模块
```

等待用户输入分析范围。

### 第2步：收集项目信息

对于指定范围，进行以下调查：

1. **项目结构**
   - 目录结构和技术栈
   - 主要入口文件和配置文件

2. **模块清单**
   - 已有哪些模块
   - 模块间的依赖关系

3. **代码规模**
   - 各模块代码行数
   - 文件数量统计

### 第3步：功能完成度分析

对每个模块分析以下方面：

| 维度 | 检查项 |
|------|--------|
| 文件完整性 | 核心文件是否存在 |
| 功能覆盖 | 主要功能是否实现 |
| 接口完整性 | API 接口是否完整 |
| 边界处理 | 错误处理、验证是否完善 |
| 测试覆盖 | 是否有单元测试/集成测试 |
| 文档情况 | 是否有注释/文档 |

### 第4步：生成分析报告

将分析结果保存到 `.gdf/analysis/{时间戳}-analysis.md`

参考模板 `../templates/project-analysis.md` 生成报告。

### 第5步：输出总结

```
---

📊 项目分析完成！

整体完成度：X%

模块完成度：
- [模块1]: XX%
- [模块2]: XX%
- ...

待完成任务：N 项
发现问题：M 个

需要生成详细报告吗？
- 输入 `报告` - 生成完整分析报告文件
- 输入 `待办` - 基于分析生成待办任务
- 输入 `跳过` - 结束分析
```

### 第6步：后续操作

根据用户选择执行：

- **生成报告**：将报告保存到 `.gdf/analysis/` 目录
- **生成待办**：调用 `gdf-split` 准备任务拆分
- **跳过**：结束分析

## 注意事项

1. **使用模板**：生成报告时参考 `../templates/project-analysis.md`
2. **客观评估**：基于代码实际情况，不猜测
3. **重点突出**：优先指出影响功能的问题
4. **可执行建议**：建议要具体可执行
5. **尊重现有代码**：不盲目批评已有实现
6. **保留分析结果**：分析报告保存到 `.gdf/analysis/`

## 前置条件

- 无（可随时执行）
- 如果需要参考项目规范，先确保 `gdf-init` 已执行
