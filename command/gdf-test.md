# gdf-test - 测试验证指令
version: 1.0.0

## 触发条件
用户输入 `gdf-test`

## 执行时机
- AI 生成代码后需要验证功能
- 开发完成一个模块后
- 进行回归测试时
- 代码重构后验证功能

## 执行流程

### 第1步：询问测试内容

输出：

```
🧪 测试验证

请描述需要测试的内容：

1. 输入模块名称（如 `user` / `order`）- 测试指定模块
2. 输入 `本次` - 测试本次开发的内容
3. 输入 `全部` - 测试整个项目
4. 粘贴测试需求描述
```

等待用户输入。

### 第2步：收集测试信息

根据用户输入，确定：

1. **测试范围**
   - 指定模块 / 本次开发 / 全部项目

2. **测试类型**
   - 功能测试
   - 边界测试
   - 错误处理测试
   - 性能测试（可选）

3. **现有测试**
   - 是否已有测试代码
   - 测试覆盖情况

### 第3步：分析待测代码

对测试范围内的代码进行分析：

| 检查项 | 说明 |
|--------|------|
| 输入验证 | 参数校验是否完善 |
| 边界条件 | 边界值处理 |
| 异常处理 | 错误捕获和返回 |
| 返回值 | 返回值是否正确 |
| 副作用 | 对外部状态的影响 |

### 第4步：设计测试用例

基于模板 `../templates/test-report.md` 中的测试用例设计部分，生成测试用例。

### 第5步：执行测试

询问用户执行方式：

```
测试执行方式：
1. 输入 `运行` - 在项目中运行测试
2. 输入 `生成` - 生成测试代码（需手动运行）
3. 输入 `跳过` - 仅生成测试计划
```

根据用户选择执行：
- **运行**：尝试运行现有测试或新生成测试
- **生成**：生成测试代码文件
- **跳过**：只输出测试计划和用例设计

### 第6步：生成测试报告

将测试结果保存到 `.gdf/test/{模块名}-test-{时间戳}.md`

参考模板 `../templates/test-report.md` 生成报告。

### 第7步：输出总结

```
---

🧪 测试验证完成！

测试范围：[模块名]
通过：N 个
失败：N 个

测试报告已保存到：.gdf/test/xxx.md

需要修复问题吗？
- 输入 `修复 [问题编号]` - 修复指定问题
- 输入 `详情` - 查看完整测试报告
- 输入 `下一步` - 继续开发流程
```

## 注意事项

1. **使用模板**：生成报告时参考 `../templates/test-report.md`
2. **不破坏现有测试**：如果已有测试，先确保通过
3. **客观评估**：基于实际运行结果，不猜测
4. **记录问题**：发现的问题要详细记录
5. **可复现**：问题描述要能复现
6. **保留报告**：测试报告保存到 `.gdf/test/`

## 前置条件

- 已完成至少一个模块的开发（`gdf-new`）
- 或已有可测试的代码
